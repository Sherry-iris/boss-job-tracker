# 使用说明

> 配套脚本：[`boss-job-tracker.user.js`](../boss-job-tracker.user.js)

---

## 一、安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 点 Tampermonkey 图标 → **添加新脚本**。
3. `Ctrl+A` 全选删除模板 → 粘贴脚本全部内容 → `Ctrl+S`。
4. 打开 `https://www.zhipin.com`，右下角出现绿色圆形「追踪」按钮即成功。

**Edge 用户**：`edge://extensions` 左下角的「开发人员模式」必须打开；若开了「增强的安全模式」，需把 `zhipin.com` 加入例外。

---

## 二、第一次用：告诉它你关注谁

这一步不做，脚本不知道要记录什么。

1. 点右下角「追踪」→ 切到 **企业** 页签。
2. 输入公司名，回车。可以连着加好几家。
3. 名字写关键部分就够，比如「蚂蚁」「网易」「字节」。匹配是模糊的，会自动忽略「有限公司」「（杭州）」这类后缀。
4. 建议 6–20 家。

---

## 三、日常使用

- 照常在 BOSS 上浏览：搜索结果页、公司职位页都可以。停留两秒左右，脚本自动扫描当前页。
- 属于关注公司的岗位被记录，卡片上出现状态角标，**7 天内首次发现**的卡片带橙色描边。
- 右下角悬浮球上的红色数字 = 近 7 天新增岗位数。
- 点悬浮球看汇总：概览 / 岗位 / 企业 / 设置。

**状态流转**：待看 → 已投递 → 已沟通 → 待面试 → 已面试 → Offer / 已结束。在岗位列表里下拉切换，改完立刻保存。

**关键词标星**：设置页维护关键词（默认带 HRBP、招聘、人力资源、组织发展、校招、培训），标题或标签命中的岗位前面出现 ★。

---

## 四、修改关注的企业和岗位

### 企业

| 想做什么 | 操作 |
|---|---|
| 添加 | 企业页签 → 输入公司名回车 |
| 删除 | 该行右侧「删除」。删掉后不再采集这家公司的新岗位，**已记录的岗位会保留**在列表里 |
| 加别名 | 该行右侧「别名」。BOSS 上的公司名与清单对不上时用它，多个用逗号分隔 |
| 把采集到的其他公司转为关注 | 企业页下方「采集到的其他公司」→ 点「加入关注」，之前采集的岗位会自动归入 |

### 岗位

| 想做什么 | 操作 |
|---|---|
| 改状态 | 岗位页签 → 每行右侧下拉框 |
| 删除单个岗位 | 每行最右边的「×」。岗位下架、不感兴趣、投错了都用它，**删掉之后不会再被采集回来** |
| 找回误删 | 设置页 →「恢复已移除的 N 个岗位」 |
| 筛选 | 搜索框 + 工作地点 + 工作年限 + 企业 + 状态 + 只看新增，六项可叠加 |

## 五、筛选说明

### 工作年限

不照抄 BOSS 的标签文字，归成 7 类：

| 分类 | 判定依据 |
|---|---|
| 实习 | 标题或标签含「实习」，或薪资按天计（`200元/天`） |
| 校招 | 含「校招 / 应届 / 在校 / 管培」 |
| 1-3 年 | 含 1-3年、1年以内 |
| 3-5 年 | 含 3-5年 |
| 5-10 年 | 含 5-10年 |
| 10 年以上 | 含 10年以上 |
| 经验不限 | 以上都不沾 |

实习单独靠「按天计薪」辅助识别，因为 BOSS 上大量实习岗的年限标签写的是「在校/应届」，与校招混在一起。

### 工作地点

取岗位卡片里的城市（「杭州·西湖区」→ 杭州），下拉按岗位数量排序。卡片里取不到时会退而从标签中匹配常见城市名。

## 六、数据在哪里

存在 Tampermonkey 的本地存储（`GM_setValue`）里，只在这台电脑的这个浏览器上。

> **换电脑 / 重装浏览器前，去设置页点「导出 JSON 备份」。** 新环境装好脚本后点「导入 JSON」即可合并。
> 「导出 CSV」是给 Excel 看的，不能导回来。

---

## 七、必须知道的限制

1. **只在你浏览时采集。** 关掉浏览器它就不工作，也不会主动通知你。想知道有没有新岗位，打开 BOSS 看一眼悬浮球上的数字。
2. **不抓取、不请求接口。** 所有数据都从你眼前这个页面里读，等同你自己看了一遍再记下来。不触发平台风控。
3. **依赖 BOSS 的页面结构。** 平台改版可能导致识别失效（表现为看板一直空着）。脚本做了多重兜底，但不是万无一失。

---

## 八、采集不到的时候

按顺序排查：

1. **企业页里有没有这家公司？名字能不能对上？** 这是最常见原因——脚本只记录关注清单里的公司，清单外的岗位会被静默跳过。
2. 在职位列表页把列表滚一滚让岗位加载出来，再点「设置 → 立即重新采集当前页」，会提示识别了几个。
3. 仍然为空：F12 打开控制台，输入 `__bossTracker.scan()`，把返回值和页面截图发到 GitHub Issues。

## 九、常见问题

**Q：能自动推送微信吗？**
不能。当前设计只做本地记录，不做主动通知。要真推送需要有常开的后端或云服务，那会显著提高被风控识别概率，所以没有做。

**Q：会重复记录同一个岗位吗？**
不会。按 BOSS 的 jobId 去重，同一岗位只会有一条记录，再次扫到只更新最后见到时间。

**Q：为什么状态是「待看」，我没设过？**
新记录的岗位默认状态都是待看，等你投递后再手动改成「已投递」。

**Q：数据能同步到手机吗？**
不能自动同步。可以用「导出 JSON → 导入」的方式手动搬，或者把数据放在支持同步的目录里自行处理。
