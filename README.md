# BOSS 岗位追踪台

> 你在 BOSS 直聘上正常刷岗位，它顺手把你关注公司的岗位记下来，汇总成一个本地看板。

![version](https://img.shields.io/badge/version-1.2.1-0F6E56)
![license](https://img.shields.io/badge/license-MIT-blue)
![platform](https://img.shields.io/badge/platform-Tampermonkey%20%7C%20Violentmonkey-orange)

一个 Tampermonkey 用户脚本。**不爬取、不发请求、不上传数据**，只读取你当前页面上已经渲染出来的岗位卡片。

---

## 它解决什么问题

找工作的时候，很多人心里有一份「目标公司清单」——十来家想去的公司。麻烦在于：

- 每天要去这十几家公司的招聘主页各看一遍，有没有新岗位
- 岗位散落在搜索结果页、公司页、推荐流里，看过就忘
- 投了哪些、哪些在等回复、哪些已经挂了，全靠脑子记

BOSS 自带的「关注公司」能提醒你有新职位，但只给你一个消息流，没有汇总视图，也不能按「我想投的条件」筛。

这个脚本补的是后半段：**采集交给你正常的浏览行为，整理和追踪交给它。**

---

## 功能

| 功能 | 说明 |
|---|---|
| **自动采集** | 你在 BOSS 上浏览时自动记录关注企业的岗位，滚动加载也会跟着记录，不需要点任何按钮 |
| **新岗位高亮** | 7 天内首次发现的岗位带橙色描边，右下角悬浮球显示新增数量 |
| **汇总看板** | 四个页签：概览 / 岗位 / 企业 / 设置 |
| **多维筛选** | 工作地点、工作年限、企业、状态、关键词，任意叠加 |
| **状态追踪** | 待看 → 已投递 → 已沟通 → 待面试 → 已面试 → Offer / 已结束 |
| **企业别名** | BOSS 上的公司名和你记的对不上时，加个别名修正匹配 |
| **关键词标星** | 标题或标签命中关键词（如 HRBP、招聘、校招）的岗位自动标星 |
| **数据自主** | 数据只存在本地，支持导出 JSON 备份与 CSV（Excel 可看） |

### 工作年限是怎么分类的

不照抄 BOSS 的标签文字（写法不统一），而是归一化成 7 类，按「我能不能投」来分：

| 分类 | 判定依据 |
|---|---|
| 实习 | 标题或标签含「实习」，**或薪资按天计**（如 `200元/天`） |
| 校招 | 含「校招 / 应届 / 在校 / 管培」 |
| 1-3 年 | 含 1-3年、1年以内 |
| 3-5 年 / 5-10 年 / 10 年以上 | 按标签对应匹配 |
| 经验不限 | 以上都不沾 |

实习和校招特意分开：BOSS 上很多实习岗的年限标签写的是「在校/应届」，和校招混在一起，只看标签分不开，而这两类岗位的投递策略完全不同。

## 先看界面

不想装任何东西也可以先看效果。`demo/index.html` 是一个纯静态演示页：用模拟数据预置本地存储，再加载真实脚本，所以看到的就是实际界面。

本地预览二选一：

- 直接双击打开 `demo/index.html`
- 或在仓库目录启动静态服务：`python -m http.server 8899`，然后访问 `http://localhost:8899/demo/`

如果这个仓库开启了 GitHub Pages，访问 `/demo/` 即可在线查看。

> 演示页里全是假数据，不会请求 BOSS，也不会写入你的账号信息。

## 安装

### 前置：装一个用户脚本管理器

- Chrome / Edge：[Tampermonkey](https://www.tampermonkey.net/)
- Firefox：[Tampermonkey](https://www.tampermonkey.net/) 或 [Violentmonkey](https://violentmonkey.github.io/)

> **Edge 用户注意**：打开 `edge://extensions`，左下角的「开发人员模式」必须打开，否则 Tampermonkey 无法运行任何用户脚本。
> 如果 Edge 开了「增强的安全模式」，还需要在设置里把 `zhipin.com` 加入例外，或把模式调成「平衡」。

### 方式一：一键安装

装好 Tampermonkey 后，点击下面的链接，会弹出安装确认页：

```
https://raw.githubusercontent.com/zxr0803/boss-job-tracker/main/boss-job-tracker.user.js
```

### 方式二：手动安装

1. 下载本仓库的 `boss-job-tracker.user.js`
2. 点浏览器右上角 Tampermonkey 图标 → **添加新脚本**
3. `Ctrl+A` 全选删掉编辑器里的模板，粘贴脚本全部内容
4. `Ctrl+S` 保存

> 也可以直接把 `.user.js` 文件拖进浏览器窗口，Tampermonkey 会自动弹出安装页。

## 快速开始

**第 1 步 · 告诉它你关注谁**

点右下角绿色「追踪」悬浮球 → **企业** 页签 → 输入公司名回车。

名字写关键部分就够，比如「蚂蚁」「网易」「字节」——匹配是模糊的，会自动忽略「有限公司」「（杭州）」这类后缀。建议加 6–20 家。

**第 2 步 · 正常刷 BOSS**

搜索结果页、公司职位页都可以。停留两秒左右，脚本会自动扫描当前页。属于关注公司的岗位会被记下来，卡片上出现状态角标。

**第 3 步 · 回头看板**

点悬浮球，四个页签各管一件事：

- **概览** — 在招岗位数、近 7 天新增、7 日走势、企业活跃度
- **岗位** — 六个条件筛选，直接改投递状态，不需要的岗位可以删
- **企业** — 关注名单管理、别名、采集到的其他公司一键转关注
- **设置** — 关键词、采集开关、导出导入、清空数据

详细操作见 [docs/usage.md](docs/usage.md)。

## 工作原理

这部分值得说清楚，因为它决定了你要承担什么风险：

1. **不请求接口、不模拟登录、不破解风控。** 脚本只在你已经打开的页面上，读取 DOM 里已经渲染出的岗位卡片。从这个角度说，它做的事情等同「你自己看了一遍，然后记在 Excel 里」。
2. **不修改页面数据，不代替你操作。** 不会自动投递、不会自动打招呼。
3. **数据不出本地。** 存在 Tampermonkey 的本地存储（`GM_setValue`）里，没有任何上报。
4. **不开后台进程。** 你不开 BOSS 页面，它就不工作，也不会给你推送。

第 4 条是设计上的取舍，不是缺陷。要做到「关掉浏览器也能提醒你」，必须有常开后端或云服务，那是另一个量级的复杂度，也会显著提高被平台风控识别的概率。

## 常见问题

<details>
<summary><b>浏览了半天，一个岗位都没记录</b></summary>

按顺序检查：

1. **企业页里加了这家公司吗？** 这是最常见的原因。脚本只记录关注清单里的公司。
2. **公司名对得上吗？** 页面上显示「某某网络科技（杭州）有限公司」，你清单里写的是「某某」——通常能匹配；但如果差异较大，用企业行的「别名」按钮补一个。
3. **当前页是不是职位列表页？** 消息页、简历页、首页推荐流上没有岗位卡片。
4. **企业名太短或太泛？** 少于两个字的关键词会被跳过，避免误匹配。

调试用：F12 打开控制台，输入 `__bossTracker.scan()`，会返回本次识别到的岗位数与新增数。

</details>

<details>
<summary><b>换电脑 / 重装浏览器，数据会丢吗</b></summary>

会。数据存在浏览器本地。**换环境前先去设置页点「导出 JSON 备份」**，新环境装好脚本后点「导入 JSON」合并回来。

「导出 CSV」是给 Excel 看的，不能导回来。

</details>

<details>
<summary><b>搜索框输入中文没反应</b></summary>

已在 v1.2.1 修复。如果仍有问题，请确认你装的是最新版本。

</details>

<details>
<summary><b>会导致 BOSS 账号被限制吗</b></summary>

脚本不额外发送任何请求，行为上等同于你手动浏览，因此风险很低。但任何自动化辅助工具都无法给出零风险保证——**账号是你自己的，请自行判断**。想更保守的话，只用它做记录、不做高频刷新。

</details>

<details>
<summary><b>支持哪些浏览器</b></summary>

Chrome、Edge、Firefox 等支持 Tampermonkey / Violentmonkey 的 Chromium 或 Gecko 内核浏览器。Safari 未测试。

</details>

## 开发

### 调试接口

脚本在页面上暴露了 `window.__bossTracker`：

```js
__bossTracker.scan()        // 手动扫描当前页，返回 { total, added, updated }
__bossTracker.decorate()    // 重新给岗位卡片打状态角标
__bossTracker.state()       // 读取当前存储的完整状态
__bossTracker.expKeyOf(job) // 查看某个岗位的年限分类
__bossTracker.cityOf(job)   // 查看某个岗位的城市
__bossTracker.reset()       // 清空所有数据
```

### 文件结构

```
boss-job-tracker.user.js   # 全部逻辑（单文件，无依赖）
demo/index.html            # 用假数据跑的演示页，可直接打开看界面
docs/usage.md              # 详细使用说明
CHANGELOG.md               # 版本记录
```

### 本地开发

脚本是单文件、无构建、无依赖。改完直接覆盖 Tampermonkey 里的脚本内容即可，刷新 BOSS 页面生效。

采集逻辑依赖 BOSS 的页面结构，主要靠类名模糊匹配（`[class*="job-name"]` 等）+ 文本行解析兜底。**BOSS 改版可能导致识别失效**，欢迎提 Issue 附页面截图。
